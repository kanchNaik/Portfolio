Cancer Pathology – Multimodal AI Project

This project uses AI to help classify cancer from pathology images. It combines computer vision and large language models (LLMs) to improve both accuracy and explainability for real clinical use.

🔍 Goal:
Improve cancer detection using images + language, and make AI predictions easier to understand for doctors.


🧠 Approach:
Built a multimodal pipeline using image captioning, advanced prompting, and retrieval of similar cases to support each decision.

💬 Prompting Techniques:
Used GPT‑4o and LLaVA with:

  • Zero‑shot and Few‑shot prompts (for low data use)
  • Chain‑of‑Thought (CoT) – step-by-step reasoning
  • Tree‑of‑Thought (ToT) – multiple reasoning paths


📡 Retrieval-Augmented Generation (RAG):
Combined CLIP and Sentence Transformers to find similar past cases. Helped generate more informative and reliable outputs.


🔧 Fine-Tuning:
Used LoRA (efficient fine-tuning) on:

  • ViT‑B/16 – for image-only baseline
  • BLIP‑2 + GPT‑2 – for generating captions from medical images
  • LLaVA – fine-tuned on captioned medical image pairs

✨ What’s Different:

  • Caption-guided instruction tuning for better medical understanding
  • Dual retrieval: visual + semantic (RAG)
  • Compared CoT and ToT reasoning in real diagnostic scenarios
  • Balanced accuracy with explainability

📈 Performance:
ViT + LoRA: 87% Accuracy / 87.5% Recall
RAG + CoT: up to 88.6% Recall with better interpretability

📚 Datasets:
PCam (binary cancer), PatchGastricADC22 (annotated gastric cancer), BIOMEDICA (image + caption pairs)

🛠 Tech Stack:
Python, PyTorch, HuggingFace, CLIP, BLIP‑2, FAISS, GPT‑4o, LLaVA

This project brings AI closer to real clinical use — by combining strong performance with clear, step-by-step explanations.

💡 What's Unique:

  • Multi-round adaptive feedback like a real interviewer

Agentic AI – Multi-Agent Code Generation System

A modular AI system that turns natural language requests into full-stack code (frontend + backend) using autonomous agents, Retrieval-Augmented Generation (RAG), and validation pipelines. Built to simulate human-like coordination and intelligent feedback-driven iteration.

🎯 Goal:
Convert user prompts into structured, production-grade code using API docs, RAG, and validation — with a multi-agent architecture that adapts to feedback and evolves through sessions.


🧠 Key Agents:

  • System Orchestrator: Central controller that delegates tasks to other agents
  • Instruction Parser: Breaks the prompt into subtasks
  • Retriever (RAG): Finds relevant API info from embedded CSV docs using FAISS + metadata
  • Code Generator: Builds code using subtasks + API docs with GPT-4 or open LLMs
  • Validator: Checks syntax, linting, API match, and security before delivering code
  • Feedback Agent: Captures approval or structured user feedback
  • State Manager: Stores session history, validation status, feedback, and retry count

🔁 Feedback Loop:
If user rejects the code or validator fails → system automatically re-prompts using session context, prior output, and user feedback for accurate regeneration.

📦 RAG & Embedding Setup:

  • Embedding Model: bge-small-en (384-dim)
  • Storage: FAISS vector DB + metadata dictionary
  • Documents: API docs parsed from web (via Playwright + BeautifulSoup)

🤖 Code Generation:
Supports dev stack choice (e.g., React, Flask, Node), generates both frontend and backend code using GPT-4 (or Mistral/LLaMA as fallback). Prompts include subtasks, API params, and context from RAG.


🧪 Validation Pipeline:
Code is passed through syntax checking, linting, API validation, and security scan. Failed results are captured, feedback is collected, and new prompts are generated iteratively.

⚙️ Tech Stack:
Python, GPT-4, FAISS, Sentence-BERT, Playwright, BeautifulSoup, Mistral, LangChain, Autogen, Pydantic

The architecture supports real-time agent communication, auto-repair feedback loops, and scalable task planning — laying the foundation for future multi-agent developer tools.

Emotion-Aware Dialogue Generation

A research-driven NLP project that brings characters to life using emotionally aware dialogue systems. It combines deep learning with psychology — modeling how personality, mood, and emotional states evolve across conversations.

🎯 Goal:
Predict future emotions in dialogue using the speaker’s personality (OCEAN), mood transitions, and past utterances. Generate emotionally intelligent and psychologically consistent responses.


💡 Motivation:
Most chatbots ignore emotional flow and personality. Our system adds both — making responses feel more human, natural, and emotionally coherent.

🧠 Core Techniques:

  • Emotion Modeling: Emotions encoded in Valence-Arousal-Dominance (VAD) space.
  • Personality: Uses the Big Five OCEAN traits, projected into VAD to influence mood shifts.
  • Mood Tracking: Models evolving emotional state across dialogue turns.

🧪 Models & Experiments:

  • Multi-Head Attention (VAD-guided): Token-level emotional focus
  • Graph Neural Network (GNN): Utterance-personality relationships via graph structure
  • HTN + GRU: Hierarchical transformers + GRU for mood transitions
  • Autoencoder: Joint emotion + mood reconstruction
  • TCN (Temporal ConvNet): Best performer for capturing emotion evolution
  • BERT + BiGRU: Strong contextual baseline with VAD-personality fusion

📊 Best Performance:
TCN model achieved: Micro-F1 = 0.55, Macro-F1 = 0.43 Strong per-class F1 on Neutral, Joy, Surprise, Anger Autoencoder had best results on rare classes like Disgust


📚 Dataset:
PELD – Personality-Affected Emotion Lines Dataset (from Friends TV show) 6,510 dialogue samples with utterances, emotion labels, and personality profiles (OCEAN)

🛠 Tech Stack:
Python, PyTorch, Transformers, HuggingFace, BERT, GRU, GCN, TCN, FAISS

This project combines linguistics, psychology, and AI to model not just what is said, but how it's said and felt — enabling deeper, more believable conversational agents.

AI-Powered Customer Support Bot (RAG + FAQ + Tickets)

A production-ready support assistant built with Next.js and Supabase. It answers product questions using Retrieval-Augmented Generation (RAG), cites exact FAQs, and—when confidence is low—creates a structured support ticket with an LLM-written summary of the conversation.

🔍 Goal
Give users fast, accurate answers from your existing FAQs and streamline hand-off to human support when needed, all on a zero-to-low cost stack suitable for students and early teams.


✨ What It Does

  • Chat to Answer: Users ask questions; the bot finds the best FAQ passages and answers with inline citations like [FAQ-12].
  • Confidence Guardrails: If similarity is low, it asks a targeted follow-up instead of guessing.
  • Create Tickets from Chat: On request (or low confidence), it summarizes the entire conversation (title, steps, environment, FAQ refs) and opens a ticket.
  • Signed-in History: Logged-in users get a left-sidebar with conversations; the latest opens automatically.
  • Admin-free Seeding: Seed FAQs from CSV/Hugging Face datasets into Supabase with a one-time API route.

🧠 Architecture (High-Level Flow)

  • User UI (Next.js): Two-pane chat — left: conversations + “New chat”, right: conversation thread.
  • RAG: Query is embedded → vector similarity in Postgres (pgvector) → top FAQs returned.
  • Answering: Small LLM (Groq) writes a concise response grounded in the retrieved FAQs; adds [FAQ-id] citations.
  • Ticketing: If asked (or low confidence), LLM summarizes the entire chat (packed to model context), infers environment (web/iOS/Android/API), extracts FAQ refs, and creates a Supabase ticket.
  • Auth + Data: Supabase stores users, conversations, messages, FAQs, embeddings, and tickets with RLS on all user data.
  • Deployment: Vercel (App Router) for serverless API routes and UI; environment variables keep keys secure.

🗃️ Data & RAG Details

  • FAQ tables: faq(id, question, answer), faq_embeddings(faq_id, embedding vector) with pgvector.
  • Retrieval RPC: a Postgres function (e.g., match_faq) performs cosine similarity against embeddings and returns { id, question, answer, similarity }.
  • Guardrails: thresholds like MIN_SIM and STRONG_SIM prevent hallucinations and control follow-ups.
  • Seeding: CSV/Hugging Face ingestion endpoint with dedupe via unique index on lower(question).

🔤 Models

  • Embeddings: Hugging Face Inference — BAAI/bge-small-en-v1.5 (384-d) via token in env (HF_TOKEN).
  • LLM (answers & tickets): Groq llama-3.1-8b-instant (GROQ_API_KEY), optimized for low latency and tight budgets.
  • Context Packing: Entire conversation is loaded; oldest portion is auto-compressed if it would exceed the model’s context window. Recent turns remain verbatim.

🛡️ Auth, Privacy & Policies

  • Auth: Supabase email/password (UI hides magic link/third-party if not enabled).
  • RLS: Row-Level Security on conversations, messages, and tickets ensures users can only access their own data.
  • Safety: No free-text hallucinations on low confidence; bot asks a follow-up or escalates.

🧩 API Endpoints

  • POST /api/answer — stateless RAG answer with citations.
  • POST /api/chat — stateful chat; persists messages when logged in; can escalate to ticket.
  • GET /api/my/conversations — list user conversations (title + last activity).
  • GET /api/my/messages?id=… — messages for a conversation.
  • GET /api/my/tickets — list current user’s tickets.
  • POST /api/seed-faq — seed FAQs (CSV/HF dataset), with optional ?force=true.

🖥️ UI Highlights

  • Two-pane layout: sidebar (history + “New chat”) and main chat thread.
  • “Create ticket” button: summarizes the whole chat, attaches FAQ refs, and inserts ticket.
  • Tickets page: list + detail view (title, status, priority, created, summary).
  • Light/Dark theme with improved readability (no white-on-white text).

⚙️ Tech Stack

  • Frontend / Hosting: Next.js (App Router), Tailwind, Vercel
  • Backend / DB: Supabase (Postgres, Auth, RLS, Edge functions optional)
  • Vector Search: pgvector + SQL RPC
  • LLM / Embeddings: Groq (Llama-3.1-8b-instant), HF Inference (BGE small)
  • Infra: Environment variables for keys; serverless API routes

🚀 How to Try

  • Open the Support page and ask a product question.
  • If the bot isn’t fully confident, it will ask a quick follow-up.
  • Click “Create ticket” to escalate — sign in if prompted.
  • Visit the Tickets page to see your structured summary and status.

Built to be fast, frugal, and practical: accurate answers when possible, and a clean hand-off to humans when not.
